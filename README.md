# 空手道場マネージャー

空手道場の **顧客管理・指導記録・会員向けコンテンツ配信・メール配信** を 1 つにまとめた Web アプリです。
指導者は生徒名簿から出欠・習熟度・審査対象者までを一元管理でき、生徒（会員）は自分の帯に応じて解放される
コンテンツを閲覧したり、スマホで撮った稽古動画を提出してアドバイスをもらえます。

外部ライブラリを使っていないため、`npm install` は不要です（Node.js 22.5 以降に同梱の `node:sqlite` を利用）。

## 動かし方

```bash
npm run seed     # サンプルデータを投入（初回のみ。作り直すときは npm run reset）
npm start        # http://localhost:3000 で起動
npm test         # テスト（31 件）
```

初期ログイン:

| 役割   | メールアドレス        | パスワード |
| ------ | --------------------- | ---------- |
| 指導者 | `sensei@dojo.test`    | `dojo1234` |
| 会員   | `takumi@example.com`  | `dojo1234` |

## できること

### 指導者向け

| 画面             | 内容 |
| ---------------- | ---- |
| ダッシュボード   | 在籍数・今月の稽古回数・審査対象者・未添削動画・帯別在籍・直近の予定 |
| 生徒名簿         | 氏名／ふりがな／生年月日／支部／帯／入会日／連絡先／保護者／プラン／在籍状況の登録・検索 |
| 生徒カルテ       | スタンプ台紙と押印履歴、審査判定、習熟度チェックリスト、出欠履歴、提出動画、LINE 連携、ログインアカウント発行 |
| 出欠             | 稽古を作成し、在籍者を一覧で出席／遅刻／欠席にチェック（保存と同時にスタンプを押す） |
| スタンプ         | 稽古から一括押印、生徒を選んで押印、取り消し、押印ログ（監査用） |
| 審査             | 条件を満たす生徒の自動抽出、審査会の作成、受審者登録、合否入力（合格で帯が自動更新） |
| フォーム添削     | 生徒から届いた動画を再生し、一言アドバイスと点数を返す |
| コンテンツ       | 記事・動画の投稿。閲覧に必要な帯とプレミアム限定かどうかを設定 |
| 試合・イベント   | 大会・合宿・講習会の掲載、エントリー者の確認、案内の一括作成 |
| 連絡（メール/LINE）| 配信対象の絞り込み、差し込み文字、テンプレート、下書き確認、一括送信、送信ログ |
| 支部設定         | 支部ごとのスタンプ必要数・審査ルール・LINE 連携の可否・割引の有無 |

### 会員向け

- **マイページ** — スタンプ台紙（閲覧のみ）、審査までの残り個数、解放したコンテンツ数
- **学びの部屋** — 帯が上がると解放されるコンテンツ（空手・栄養・トレーニング・仕事／法律）
- **フォーム添削** — スマホ動画をアップロードして指導者からアドバイスをもらう
- **試合・イベント** — 予定の確認とエントリー

### スタンプカード（出席の記録と割引）

本部のスタンプカード制をそのままアプリにしたものです。**スタンプを押せるのは指導者だけ**で、
生徒側の画面（マイページ）には押印ボタンがありません。自己申告で出席を水増しできない作りです。

- **押し方は 2 通り**
  - 出欠画面で保存 → 「出席」「遅刻」の生徒に自動で 1 個ずつ（同じ稽古で二重に押されない）
  - スタンプ画面で生徒を選んで押す（大会参加・他支部での稽古など、理由を入れて 1 個）
- **取り消し** — 押し間違いは取り消せます。行は消えず「誰がいつ取り消したか」が残ります
- **出欠を欠席に直す** と、その稽古のスタンプは自動で取り消されます
- **押印ログ** — 誰が・いつ・どの生徒に・どの理由で押したかを一覧で確認できます（監査用）

**台紙 1 枚 = 30 個**（支部設定で変更可）。1 枚たまると審査の受験資格になります。
審査用の台紙は既定で**昇級のたびに数え直し**です（支部設定「昇級後のスタンプ」で通算のままにもできます）。

#### 月謝割引（既定オフ）

審査料を現金で徴収する運用では不要なため、**割引は既定でオフ**にしてあり、
指導者画面にも生徒画面にも割引の表示は出ません。支部設定の「割引を → 使う」で有効にすると、
台紙 2 枚目以降 1 枚ごとに 1 段階ずつ増えます（既定 500 円 / 枚、上限 6 段階）。

| 台紙 | 割引オンのときの効果 |
| ---- | ---- |
| 1 枚目（30 個） | 審査の受験資格のみ |
| 2 枚目（60 個） | 割引 1 段階 |
| 3 枚目（90 個） | 割引 2 段階 … 上限まで |

割引段階は**通算のスタンプ数**で決まるので、昇級しても下がりません。

なお、月謝そのもの（引き落とし先や決済業者）は支部ごとに異なるためアプリでは扱っていません。
割引は金額の算出までで、請求とは連動しません。

### 審査対象者の判定ルール

支部設定 `exam_rule` で選べます。既定は本部方式の「スタンプ」です。

| ルール | 条件 |
| ------ | ---- |
| `stamp`（既定） | スタンプが台紙 1 枚分たまったら受験資格 |
| `stamp_skill` | スタンプ＋その帯の技術項目の 80% 以上が「できる」以上 |
| `criteria` | 出席回数・在籍期間・習熟度の 3 条件（回数と月数は帯ごとに `belts.min_sessions` / `belts.min_months` で設定） |

どのルールでも、条件を満たしていない生徒をカルテから **手動で審査対象に指定** できます。

### 支部

支部ごとに、スタンプの必要数・審査ルール・割引の有無・LINE 連携の可否を別々に設定できます。
サンプルデータでは本部と名西支部の 2 つがあり、どちらも「メールのみ・割引なし」で始まります。

支部設定の画面には各支部の現在の連絡手段（例：`在籍 4 名 ／ 連絡手段：メールのみ`）が表示されるので、
切り替えた結果をその場で確認できます。

### コンテンツのアクセス制御

- `min_belt_id` … その帯以上の会員だけが閲覧可能（未設定なら全会員）
- `is_premium` … プレミアム会員（`members.plan = 'premium'`）だけが閲覧可能
- `published` … 下書きは指導者だけに見える

条件を満たさない場合、一覧では 🔒 と解放条件が表示され、詳細ページは 403 になります。
アップロードされた動画ファイル（`/uploads/...`）は **本人と指導者だけ** が取得でき、Range リクエストによる
シークにも対応しています。

## 連絡（メール / LINE）

宛先は生徒ごとに自動で決まります。

1. 所属支部で LINE 連携が有効 かつ 生徒が LINE 連携済み → **LINE**
2. それ以外 → **メール**
3. どちらも無い → 送らずに「連絡先なし」として件数に出す

LINE を使わない設定の支部は、生徒側の設定や `line_user_id` の有無にかかわらず必ずメールになります。

### あとから LINE に切り替える

支部ごとに独立しているので、ある支部だけ後から LINE を有効にできます。
連携できるようになった支部の設定で **「この支部で LINE を → 使う」** に変えて保存するだけで、
その支部の連絡が LINE 優先に切り替わります。他の支部と、その支部の未連携の生徒はメールのまま変わりません。
やめたくなったら「使わない」に戻せば、全員メールに戻ります。

### LINE 連携の手順

1. 支部設定で LINE を「使う」にし、Messaging API のチャネルアクセストークンとチャネルシークレットを入れる
2. LINE Developers の Webhook URL に `https://（公開URL）/line/webhook` を登録する
3. 生徒のカルテで「連携コードを発行」を押し、6 桁のコードを生徒に伝える
4. 生徒が道場の LINE 公式アカウントにそのコードを送ると紐づく（コードは使い捨て）

Webhook はチャネルシークレットで署名を検証し、一致しないリクエストは 401 で弾きます。

> LINE への実送信（Messaging API の push）は実アカウントでの疎通確認をしていません。
> トークン未設定または outbox モードのあいだは `data/outbox/*-line.txt` に書き出すだけで、実送信しません。

## メール送信

既定は `outbox` モードで、送信すると `data/outbox/` に `.eml` ファイルが書き出されます（実送信しません）。
実際に送る場合は環境変数を設定してください。

```bash
MAIL_TRANSPORT=smtp \
SMTP_HOST=smtp.example.com SMTP_PORT=587 \
SMTP_USER=xxx SMTP_PASS=yyy \
MAIL_FROM=dojo@example.com MAIL_FROM_NAME=○○空手道場 \
npm start
```

> SMTP クライアント（`src/mail.js`）は STARTTLS と AUTH LOGIN に対応していますが、
> 実サーバーでの疎通確認は行っていません。本番導入時はまずテスト用アドレスへ送って確認してください。

本文では `{{name}}` `{{kana}}` `{{belt}}` `{{branch}}` `{{guardian}}` `{{joined_on}}` `{{stamps}}`
`{{stamps_total}}` `{{stamps_left}}` `{{discount}}` `{{next_exam}}` `{{next_event}}` が差し込めます。
配信対象は「在籍中の全会員／審査対象者／プレミアム会員／休会中／帯を指定」から選べます。

## 環境変数

| 変数 | 既定値 | 説明 |
| ---- | ------ | ---- |
| `PORT` | `3000` | 待ち受けポート |
| `DATA_DIR` | `./data` | DB・アップロード・outbox の保存先 |
| `DB_PATH` | `$DATA_DIR/dojo.db` | SQLite ファイル |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` / `ADMIN_NAME` | `sensei@dojo.test` / `dojo1234` / `道場長` | 管理者が 1 人もいないときに作られる初期アカウント |
| `SECURE_COOKIE` | — | `1` にすると Cookie に `Secure` を付与（HTTPS 運用時） |

## ディレクトリ構成

```
src/
  server.js        HTTP サーバーとエラーハンドリング
  router.js        パスパターンのマッチング
  db.js            SQLite 接続とスキーマ
  http.js          リクエスト解析（multipart 含む）とレスポンス生成
  auth.js          パスワードハッシュ（scrypt）とセッション
  domain.js        審査判定・コンテンツ開放判定・ポイント計算
  stamps.js        スタンプの押印・取り消し・集計・割引計算／支部設定
  line.js          LINE 連携（宛先の振り分け・連携コード・署名検証・push）
  mail.js          差し込み・キュー・outbox / SMTP 送信
  routes/          画面ごとの処理
  views/           レイアウトと CSS
scripts/seed.js    サンプルデータ
tests/app.test.js  テスト
```

## 本番運用の前に

このリポジトリは**プロトタイプ**です。実際に生徒の個人情報を扱う前に、少なくとも次を用意してください。

- **HTTPS 化**（リバースプロキシ経由）と `SECURE_COOKIE=1`
- **CSRF 対策** — 現在は SameSite=Lax Cookie のみ。フォームにトークンを追加する
- **バックアップ** — `data/` ディレクトリ（DB とアップロード動画）の定期バックアップ
- **保護者同意** — 未成年の動画・写真の取り扱いについて入会時に同意を得る
- **退会時の削除フロー** — 個人情報保護法に沿った保管期間と削除の運用を決める

今後の拡張案は [docs/roadmap.md](docs/roadmap.md) にまとめています。
