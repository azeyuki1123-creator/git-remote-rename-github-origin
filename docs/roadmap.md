## フェーズ 2：実運用に入る前に必要なもの

1. **CSRF トークン** — フォーム送信の検証。今は SameSite Cookie のみ
2. **バックアップとリストア手順** — `data/` の日次バックアップ
3. **パスワード再設定** — 会員が自分でリセットできるメールフロー
4. **画像・動画の容量対策** — 現状は原寸保存。サムネイル生成と保存期間の設定
5. **監査ログの拡張** — スタンプの押印ログはあるので、個人情報の閲覧・変更にも同じ仕組みを広げる
6. **入会時の同意取得** — 動画・写真の利用、未成年の場合の保護者同意

### LINE 連携の残り作業

実装済みなのは「どちらの手段で送るかの振り分け」「連携コードによる紐づけ」「Webhook の署名検証」
「Messaging API への push 呼び出し」までです。実際に動かすには次が必要です。

1. LINE 公式アカウントと Messaging API チャネルを作る（支部ごとに 1 つ）
2. 支部設定にチャネルアクセストークンとチャネルシークレットを入れる
3. アプリを HTTPS で公開し、Webhook URL に `/line/webhook` を登録する
4. テスト用のアカウントに 1 通送って疎通を確認する

公式アカウントを持てない支部は、支部設定の LINE を「使わない」のままにしてください。
その支部の生徒は、生徒側の設定にかかわらず必ずメールに振り分けられます。

支部ごとに独立しているので、**あとから 1 支部だけ有効にする**ことができます。
提携先の準備ができたらその支部の設定を「使う」に変えて保存するだけで、他の支部には影響しません。

## フェーズ 3：有料化・拡張

### 決済（有料コンテンツのみ）

**月謝の管理はアプリの対象外**です。引き落とし先や決済業者が支部ごとに異なるため、
既存の仕組みをそのまま使う前提にしています。

決済を入れるとしたら、有料（プレミアム）コンテンツの購読だけです。一番現実的なのは Stripe で、

- Stripe Checkout でサブスクリプション（月額）を作成し、成功時に `members.plan = 'premium'` へ更新
- Webhook（`invoice.paid` / `customer.subscription.deleted`）を受けてプランを同期

の 2 点で足ります。

> 注意：受講料を継続課金で集める場合は特定商取引法に基づく表記が必要です。
> また、動画に他人が映り込む場合の肖像権、指導動画の二次利用の禁止を利用規約に明記してください。

### あると効く機能

- **出欠入力のさらなる省力化** — 押印は指導者が行う方式のまま、当日の稽古を開いた状態で
  名前をタップするだけで出席にできる一覧画面にすると、稽古後の入力が数十秒で終わります
  （生徒に自己申告させる QR チェックインは、代理読み取りで水増しできるため採用しない方針）
- **スタンプの有効期限** — 「1 年で失効」などの運用があるなら `stamps.granted_on` で絞るだけで実装できます
- **押印ログのページング** — 生徒数が増えるとログが長くなるので、日付での絞り込みを足すと見やすくなります
- **保護者アカウント** — 1 アカウントで兄弟姉妹の記録をまとめて閲覧
- **動画への時間指定コメント** — 「0:12 の引き手」のように再生位置を指定してアドバイス
- **習熟度の推移グラフ** — 帯ごとの成長を可視化して面談資料に使う
- **月謝・入金管理** — 未納者の抽出と督促メールの自動下書き
- **バッジ／称号** — 出席 100 回、皆勤賞など。ゲーム感覚をさらに強める

## 技術的な移行の目安

このプロトタイプは SQLite ＋ 標準ライブラリのみで動いており、**生徒 100〜200 名規模までは十分**です。
それを超える、または複数道場・複数指導者で同時に書き込む運用になったら、次の順で移行を検討してください。

1. DB を PostgreSQL に移す（スキーマはほぼそのまま使えます）
2. 動画を S3 互換のオブジェクトストレージに逃がす（`video_submissions.file_name` を URL に変更）
3. メール送信を SendGrid / Amazon SES などの API 送信に切り替える（`src/mail.js` の `deliver` を差し替え）
